# Offline RL Dataset Protocol

## Overview

This document describes the offline RL dataset used in the NYC Taxi Zone Recommendation project. The dataset contains trajectories generated by the DynamicSimulator v2 for Offline Policy Evaluation (OPE) and Implicit Q-Learning (IQL).

> **Important**: The dataset contains **simulator-generated trajectories**, not real driver trajectories. Performance on this dataset may not transfer to real-world deployment.

---

## 1. Trajectory Generation

### Source

Trajectories are generated by running the **DynamicSimulator v2** (src.simulator.v2.DynamicSimulator) with a specified driver policy. The simulator runs for a configurable time horizon (default: 1 week, Jan 25 - Feb 1, 2023).

### Collection Mechanism

The simulator uses an on_transition callback that records each driver's decision step as a transition:

`
For each driver at each time slot:
  1. Driver observes state (location, time, supply, demand)
  2. Driver selects action (target zone) via policy
  3. Simulator executes action:
     - If pickup succeeds: reward = fare - costs - penalties
     - If pickup fails: reward = 0
  4. Transition (s, a, r, s', done) is recorded
`

### Policies Used

| Policy | Description |
|--------|-------------|
| Random | Uniform random zone selection (exploration) |
| Stay | Driver stays in current zone |
| Baseline 1 | Highest historical demand zone |
| Baseline 2 | Demand-weighted utility |
| IQL | Offline RL trained policy |

### Episode Structure

Each "episode" is a full simulation run covering the entire time horizon. All transitions from a single simulation run share the same 	rajectory_id. This allows grouping transitions by run for trajectory-level evaluation.

---

## 2. State Definition

The state vector is **7-dimensional** and captures the current time, location, and market conditions:

| Index | Variable | Range | Description |
|-------|----------|-------|-------------|
| 0 | zone_id / 263 | [0, 1] | Normalized current zone ID |
| 1 | (hour*60 + min) / 1440 | [0, 1] | Normalized time of day |
| 2 | supply / total_taxis | [0, 1] | Supply density at current zone |
| 3 | effective_demand / 200 | [0, 1] | Normalized effective demand |
| 4 | pickup_probability | [0, 1] | Probability of finding a fare |
| 5 | supply / trips_remaining | [0, ) | Competition ratio |
| 6 | 	raffic_multiplier / 2 | [0, 1] | Normalized traffic factor |

### Rationale

- All features are **normalized** to [0, 1] for stable neural network training.
- The state captures both **spatial** (zone), **temporal** (time), and **market** (supply/demand) dimensions.
- The competition_ratio (index 5) is a novel feature capturing local driver congestion.

---

## 3. Action Definition

| Component | Description |
|-----------|-------------|
| **Action space** | 263 discrete actions (NYC taxi zones 1..263) |
| **Action meaning** | Target zone the driver relocates to |
| **Stay action** | Zone 132 (Times Square area) is the default stay location |

The action space is **all taxi zones**, allowing the policy to recommend relocation to any NYC zone.

---

## 4. Reward Definition

The reward is the **net driver profit** for a single time slot:

`
reward = fare - fuel_cost - travel_time_cost - competition_penalty - risk_penalty
`

| Component | Formula | Typical Value |
|-----------|---------|---------------|
| **Fare** | Exponential(15) + 10 | ~-40 |
| **Fuel cost** | .65/mile * distance | ~-5 |
| **Travel time cost** | .30/min * duration | ~-15 |
| **Competition penalty** | .50 * max(0, n_drivers - 1) | -25 |
| **Risk penalty** | 2.0 * (1 - pickup_probability) | -2 |

### Reward Decomposition

The reward can be decomposed into interpretable components:

`
total_revenue  = sum of trip fares
fuel_cost      = total fuel expenditure
competition    = aggregate competition penalties
risk           = aggregate risk penalties
net_reward     = total_revenue - fuel_cost - competition - risk
`

## 6. Limitations

1. **Simulator bias**: All trajectories are generated by the DynamicSimulator v2, which has known simplifications compared to real NYC taxi markets:
   - Synthetic demand patterns calibrated to aggregate statistics
   - Simplified traffic model (uniform variation)
   - No explicit passenger behavior model
   - No driver learning or adaptation within episodes

2. **Partial observability**: The state vector captures only local zone information, not global market conditions.

3. **Stationary policy**: The behavior policy is fixed during trajectory collection, while real drivers adapt over time.

4. **Distribution shift**: OPE estimates are valid only under the assumption that the target policy does not visit states far outside the training distribution.

5. **Reward misspecification**: The simulator reward includes penalties (competition, risk) that real drivers may weigh differently.

## 7. Usage

`python
from src.rl.offline import OfflineBuffer, IQLAgent
from src.simulator.v2 import DynamicSimulator

# Create buffer with enhanced fields
buffer = OfflineBuffer(capacity=10000, state_dim=7, seed=42)

# Collect trajectories from simulator
sim = DynamicSimulator()
buffer.collect_trajectories_from_v2(sim, episodes=10)

# Access enhanced fields
print(f"Trajectory IDs: {buffer.trajectory_ids[:10]}")
print(f"Timestamps: {buffer.timestamps[:10]}")
print(f"Behavior probs: {buffer.behavior_probs[:10]}")
`
